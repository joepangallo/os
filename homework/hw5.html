Problem 1Scheduling many processors

(a) Granularity is how often the parallel parts of an application must synchronize, counted in instructions run between two synchronization points. Name the grain of each workload: fine, medium, coarse, very coarse or independent.

(b) Gang scheduling runs all the threads of one application at the same moment, one thread per processor, and gives each time slice to one gang. A machine has 8 processors and three gangs: A with 8 threads, B with 4 and C with 2. A processor with no thread of the running gang sits idle, and that idle time is wasted. For each way of handing out the time, give the percentage of all processor time that is wasted, to two decimal places.

(c) A 32-core server runs a physics application with 16 threads that synchronize about every 100 instructions, next to a steady stream of short, unrelated jobs. (i) With load sharing (one global queue of ready threads that any idle core takes from), give two reasons the physics application runs poorly. (ii) With dedicated processor assignment, 16 cores belong to the application for its whole run, so a core whose thread blocks simply idles. Why can that waste be acceptable on this machine? (iii) The application's author raises the thread count to 48 on the same 16 dedicated cores, hoping for a speedup. What is likely to happen, and why?

(d) Linux's Completely Fair Scheduler gives each thread a weight from its nice value (nice 0 → 1,024; nice +3 → 526), runs the thread with the smallest virtual runtime, and adds time actually run × 1024 ÷ weight to a thread's virtual runtime after it runs. With up to 8 runnable threads, each turn comes out of a 6 ms window shared in proportion to weight. Three busy threads have nice 0, 0 and +3. Give two decimal places.

Problem 2Meeting deadlines

A periodic task (C, T) releases a job every T time units, starting at time 0. Each job needs C units of processor time and must be finished by the moment the task's next job is released (its deadline). The utilization of a set of tasks is U = C1/T1 + C2/T2 + … . Rate monotonic scheduling (RMS) gives each task a fixed priority: the shorter its period, the higher. Earliest deadline first (EDF) always runs the waiting job whose deadline is nearest. Both preempt.

(a) Tasks 1 to 3 are (C, T) = (10, 40), (15, 60) and (20, 100). Task 4, (12, 120), is then added. Give U to two decimal places and the RMS bound n(21/n − 1) to three, for n = 3 and n = 4.

(b) Task A is (C, T) = (3, 6) and task B is (4, 9). Write which task runs in each time unit from 0 to 18 under each policy: A, B, or – if the processor is idle. A job still unfinished at its deadline has missed it and is dropped (its remaining work is thrown away). Under EDF, if both waiting jobs have the same deadline, A runs.

(c) Three tasks share a resource S protected by a lock. Priorities: H high, M medium, L low; a higher-priority task that is ready always preempts a lower one.

  • L arrives at time 0 and locks S at once. It needs 3 units of work while holding S, then releases S and needs 1 more unit.
  • H arrives at time 1. It needs 1 unit of work, then locks S for 2 units, and is done when it releases S.
  • M arrives at time 2 and needs 4 units. It never uses S.

A task that asks for S while another task holds it is blocked until S is released. Under priority inheritance, the task holding S runs at the priority of the highest task blocked on S until it releases S. Under the priority ceiling protocol, S's ceiling is one level above H, and a task that locks S runs at that ceiling until it releases S. Write which task runs in each time unit (H, M, L or –).

Problem 3Moving and buffering data

Count time in processor ticks. A block of N = 16 words is read from a device that needs D ticks to produce each word. Sending a command takes 1 tick, moving one word through the processor takes 1 tick, taking an interrupt costs H = 3 ticks of overhead, setting up a DMA transfer takes 4 ticks, and each word that the DMA module moves steals 1 tick from the processor.

  • Programmed I/O: for each word the processor sends a command, polls through the D ticks, then moves the word: N(D + 2) ticks, all of them the processor's.
  • Interrupt-driven I/O: for each word the processor sends a command, does other work during the D ticks, then takes an interrupt and moves the word. The processor spends N(H + 2) ticks; the transfer ends at N(D + H + 2).
  • DMA: the processor sets up the transfer, the DMA module moves every word, and one interrupt reports the end. The processor spends 4 + N + H ticks; the transfer ends at 4 + ND + H.

(a) Fill in the table for a slow device (D = 6) and a fast one (D = 2).

(b) A process reads a file block by block. T is the time to read one block from the device, C the time the process computes on a block before it asks for the next, and M the time to copy a block from a system buffer into the process. Per block: no buffer takes T + C; a single buffer takes max[C, T] + M; a double buffer takes max[T, C + M] (the copy is counted). Give the time per block in milliseconds.

(c) A disk spins at 10,000 rpm and holds 400 sectors of 512 bytes on every track. Its arm takes s = 1 ms to start and settle plus m = 0.04 ms per track crossed; assume every seek that is needed crosses 100 tracks. Average rotational delay is half a revolution, and a sector transfers in the time it takes to pass under the head. A file of 2,000 sectors is read in two ways: sequentially, from 5 neighbouring full tracks (the first track needs a seek, a rotational delay and one full revolution to read; each later track needs only a rotational delay and one revolution), or randomly, one sector at a time from scattered places (each sector needs a seek, a rotational delay and its own transfer).

Problem 4Disk arms, disk arrays and the disk cache

A disk has tracks 0 to 199. The arm is at track 80, moving toward higher track numbers. These requests wait, in arrival order:

112 35 147 61 190 12 96 66

  • FIFO serves them in arrival order. SSTF always serves the waiting request nearest the arm.
  • SCAN serves every request it reaches while sweeping up, runs on to track 199, then turns and sweeps down. LOOK is the same but turns at the last request instead of at the edge.
  • C-SCAN sweeps up only: after the last request it runs on to track 199, returns to track 0 without serving anything, and sweeps up again. C-LOOK turns at the last request, jumps straight to the lowest waiting request, and sweeps up again.
  • Count every track the arm crosses, including runs to the edge, the return of C-SCAN and the jump of C-LOOK. The average is the total divided by the 8 requests.

(a) Fill in the table. Give the average to two decimal places.

(b) A server has 6 disks of 8 TB each. A small write changes one strip of data. Fill in the table for each way of organizing the six disks (RAID 1 uses them as three mirrored pairs).

(c) One stripe of a RAID 5 array holds four data strips, written here as 4-bit values: X0 = 1001, X1 = 0111, X2 = 1110, X3 = 0100, and a parity strip P = X0 ⊕ X1 ⊕ X2 ⊕ X3 (⊕ is exclusive-OR, bit by bit).

(d) A disk cache has 3 slots, empty at the start, and sees this string of block requests:

7 7 7 7 7 7 1 2 3 1 2 3 1 2 3

LRU replaces the block used least recently. LFU keeps a count for each cached block (1 when it is loaded, plus 1 on every hit) and replaces the block with the smallest count; among equal counts, the least recently used goes. A hit takes 0.02 ms; a miss takes 0.02 ms plus 9 ms to read the disk. Give the hit ratio to four decimal places and the average time to two.

Read it from top to bottom first; every line carries a comment. It runs three experiments:

"""rtdisk.py: deadline scheduling of periodic tasks, and a disk arm serving a stream of requests.

Run it from a terminal in the folder that holds this file:
    python rtdisk.py           (Windows)   or   python3 rtdisk.py   (macOS / Linux)

Every "random" number comes from a generator started with a fixed seed, so the task sets and the
disk requests are the same on every computer, and the few floating-point calculations (averages,
percentages, the RMS bound) print the same results everywhere: the whole output never changes.

import random  # the seeded random-number generator that builds the task sets and the disk requests
from fractions import Fraction  # exact fractions such as 2/5, so a utilization of exactly 1 is never 0.9999999
from math import gcd  # greatest common divisor, used to find the hyperperiod of a task set

SEED = 2026  # the generator's starting point; the same seed gives the same "random" numbers everywhere
DEMO = [(2, 5), (4, 7)]  # Experiment 1a: task A needs 2 units every 5, task B needs 4 units every 7, as (C, T)
NUM_TASKSETS = 3000  # Experiment 1b: how many random task sets are tested
TASKS_PER_SET = 3  # Experiment 1b: periodic tasks in each set
PERIODS = [4, 5, 6, 8, 10, 12, 15, 20]  # Experiment 1b: the periods a task may have; any three repeat within 120 units
EDGES = ["0.60", "0.70", "0.78", "0.85", "0.90", "0.95", "1"]  # Experiment 1b: the utilization ranges of the table

MEAN_GAP = 25  # Experiment 2: average time units between two arrivals

HOT_SHARE = 0.7  # Experiment 2: 7 requests in 10 go to one busy region of the disk...
HOT_FIRST, HOT_LAST = 20, 59  # ...tracks 20 to 59 (think of a busy database file); the rest go anywhere
START_TRACK = 100  # Experiment 2: where the arm starts, moving toward higher track numbers


class NotWrittenYet(Exception):  # a custom error the starter raises wherever a TODO has not been written yet
    pass  # it needs no extra behavior; its name and message say everything


# ---------------------------------------------------------------------------
# Periodic real-time tasks. A task (C, T) releases a job every T time units, starting at 0;
# each job needs C units of processor time and must finish by the next release (its deadline).
# A job still unfinished at its deadline has MISSED it and is dropped.
# ---------------------------------------------------------------------------
def hyperperiod(tasks):  # the least common multiple of the periods: after it, the whole pattern repeats
    length = 1  # the LCM so far
    for _, period in tasks:  # fold in one period at a time
        length = length * period // gcd(length, period)  # lcm(a, b) = a * b / gcd(a, b)
    return length  # simulating this many units covers every case


def utilization(tasks):  # U = C1/T1 + C2/T2 + ...: the share of the processor the tasks need
    return sum(Fraction(c, period) for c, period in tasks)  # exact, so U = 1 is exactly 1


def simulate(tasks, pick):  # run the tasks one time unit at a time; returns (missed deadlines, timeline)
    left = [0] * len(tasks)  # work still needed by each task's current job (0 = no job waiting)
    deadline = [0] * len(tasks)  # the absolute deadline of each task's current job
    missed = 0  # deadlines missed so far
    timeline = []  # one letter per time unit: who ran (A = task 0, B = task 1, ...) or "." when idle
    for now in range(hyperperiod(tasks)):  # time units 0, 1, 2, ... up to the end of the hyperperiod
        for i, (c, period) in enumerate(tasks):  # check every task for a new release
            if now % period == 0:  # task i releases a new job at this moment
                if left[i] > 0:  # its previous job is not finished, and its deadline is now...
                    missed += 1  # ...so that deadline is missed and the old job is dropped
                left[i] = c  # the new job needs C units...
                deadline[i] = now + period  # ...and must be done by the next release
        ready = [i for i in range(len(tasks)) if left[i] > 0]  # the tasks that have work waiting
        if ready:  # something can run this unit
            i = pick(tasks, ready, deadline)  # the scheduling policy chooses one of them
            left[i] -= 1  # it runs for one time unit
            timeline.append("ABCDEFGH"[i])  # record it
        else:  # nothing is waiting
            timeline.append(".")  # the processor idles
    missed += sum(1 for i in range(len(tasks)) if left[i] > 0)  # jobs whose deadline is the end of the hyperperiod
    return missed, "".join(timeline)  # the count and the timeline as one string

    return min(ready, key=lambda i: (tasks[i][1], i))  # smallest period; a tie goes to the task listed first

def random_taskset(rng):  # a random set of TASKS_PER_SET tasks whose utilization lies in the table's range
    while True:  # keep drawing until a set lands in the range

# ---------------------------------------------------------------------------
# A disk arm. Requests (arrival time, track) arrive over time. Whenever the arm is free, a policy
# chooses where it goes next: it returns (track to move to, request to serve there), or
# (track, None) to move without serving anything (to the edge of the disk, or back to track 0).
# Moving costs one time unit per track crossed; reading costs SERVICE units more.
# ---------------------------------------------------------------------------
def make_requests(rng):  # NUM_REQUESTS requests in arrival order, as (arrival time, track)
    requests = []  # the list being built
    now = 0  # arrival time of the next request
    for _ in range(NUM_REQUESTS):  # one request per trip
        now += rng.randint(1, 2 * MEAN_GAP - 1)  # the gap to it: 1 to 49 units, MEAN_GAP on average
        if rng.random() < HOT_SHARE:  # most requests...
            track = rng.randint(HOT_FIRST, HOT_LAST)  # ...go to the busy region
        else:  # the rest...
            track = rng.randrange(TRACKS)  # ...go anywhere on the disk
        requests.append((now, track))  # one request
    return requests  # the whole stream


def run_disk(requests, pick):  # serve every request with one policy; returns seek per request and every wait
    arm = START_TRACK  # where the arm is now
    state = {"up": True}  # what a policy wants to remember between calls: here, the sweep direction
    now = 0  # the clock
    arrived = 0  # how many requests have arrived so far
    pending = []  # requests that have arrived and wait for service, as positions in `requests`
    tracks_moved = 0  # total arm travel, in tracks
    wait = {}  # for each request: the time from its arrival until its data has been read
    empty_moves = 0  # moves in a row that served nothing; a correct SCAN or C-SCAN never needs more than two
    while arrived < len(requests) or pending:  # until every request is served
        while arrived < len(requests) and requests[arrived][0] <= now:  # everything that has arrived by now...
            pending.append(arrived)  # ...joins the waiting list
            arrived += 1  # next one
        if not pending:  # nothing to do...
            now = requests[arrived][0]  # ...so idle until the next arrival
            continue  # and look again
        track, chosen = pick(pending, requests, arm, state)  # the policy decides (an unwritten TODO stops here)
        tracks_moved += abs(track - arm)  # the arm crosses this many tracks...
        now += abs(track - arm)  # ...one time unit each
        arm = track  # it is there now
        empty_moves = 0 if chosen is not None else empty_moves + 1  # count the moves in a row that served nothing
        if empty_moves > 3:  # a correct policy reaches a request within two empty moves, so this one is stuck...
            raise NotWrittenYet(f"{pick.__name__} moved {empty_moves} times in a row without serving anything "  # ...so stop with a hint
                                f"(arm at track {arm}); at the edge it must turn around (TODO 2, step 4)")  # instead of looping forever
        if chosen is not None:  # a request is served at this track
            pending.remove(chosen)  # it leaves the waiting list
            now += SERVICE  # reading takes SERVICE more units
            wait[chosen] = now - requests[chosen][0]  # how long it took from arrival to done
    return tracks_moved / len(requests), wait  # average seek length per request, and all the waits


def fifo_pick(pending, requests, arm, state):  # first in, first out: the oldest waiting request
    r = min(pending)  # positions grow with arrival time, so the smallest is the oldest
    return requests[r][1], r  # go to its track and serve it


def sstf_pick(pending, requests, arm, state):  # shortest service time first: the request nearest the arm
    r = min(pending, key=lambda r: (abs(requests[r][1] - arm), r))  # fewest tracks away; a tie goes to the older one
    return requests[r][1], r  # go there and serve it

def cscan_pick(pending, requests, arm, state):  # C-SCAN: sweep up only, then return to track 0 and sweep up again
    ahead = [r for r in pending if requests[r][1] >= arm]  # requests at the arm's track or above it
    if ahead:  # something lies in the sweep's path
        r = min(ahead, key=lambda r: (requests[r][1], r))  # the lowest of them, the nearest going up
        return requests[r][1], r  # go there and serve it
    if arm < TRACKS - 1:  # nothing ahead, and the sweep has not reached the last track...
        return TRACKS - 1, None  # ...so finish the sweep
    return 0, None  # at the last track: return to track 0 without serving (counted as 199 tracks of travel)
