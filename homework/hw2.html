Problem 1Follow five processes through the seven-state model

One processor. The OS uses the seven-state model: New, Ready, Running, Blocked, Ready/Suspend, Blocked/Suspend and Exit. Whenever the running process leaves Running, the dispatcher immediately runs the process at the front of the Ready queue. A process that becomes Ready joins the back of the queue.

TimeWhat happens
0P1 is Running. The Ready queue, front to back, is P2, P3. P4 is Blocked, waiting for a disk read. P5 has just been created and is New.
2P1 asks to read input from the keyboard.
3The OS admits P5 into main memory.
5The disk finishes P4's read.
7P2's time slice runs out.
8To free main memory, the OS swaps P1 out to disk.
10P3 terminates.
12The user presses a key: the input P1 was waiting for arrives.
13The OS swaps P1 back into main memory.
15The running process asks to read from the disk.

(b) List every state transition P1 makes, with the time and the cause of each. Then give the Ready queue, front to back, at t = 16.

(c) For each transition, say whether the seven-state model allows it. If it does, describe a situation in which it happens; if not, explain why it cannot happen.

Problem 2Build an interleaved trace

A trace lists the instruction addresses the processor executes, one per instruction cycle. When several processes share one processor, their traces are interleaved with the dispatcher's.

  • Process A starts at address 4000 and executes 7 instructions (4000, 4001, …), then ends.
  • Process B starts at 6000. Its third instruction, at 6002, requests I/O, so B blocks right after executing it. The I/O does not finish before the trace ends.
  • Process C starts at 9000 and executes 10 instructions, then ends.
  • The dispatcher lives at addresses 200 to 203 and executes all four of them every time it runs. It runs between any two processes.
  • A process may run at most 5 instruction cycles before a time-out sends it to the back of the Ready queue.
  • At cycle 1, A starts running directly (no dispatcher first) and the Ready queue behind it is B, C. The trace ends when C executes its last instruction.

(a) Write the trace as a list of segments: each row is one uninterrupted stretch of A, B, C or the dispatcher. Give the addresses and the cycle numbers of its first and last instruction. Leave any unused rows empty.

(b) In which cycle does A execute its last instruction? In which cycle does C?

(c) What percentage of all the cycles in the trace belong to the dispatcher?

(d) Redo the trace in your head with a limit of 10 cycles instead of 5. How many cycles does the whole trace take now, what percentage belongs to the dispatcher, and in which cycle does A finish?

(e) The longer limit looks better on every number in (d). Give one reason an operating system would still not choose a very long limit.

Problem 5Predict what fork() prints

On UNIX systems, fork() creates a new process (the child) that is a copy of the calling process (the parent), including a copy of all of its memory. Both processes continue from the instruction right after the call. In the child, fork() returns 0; in the parent it returns the child's process ID, which is never 0. wait(NULL) makes a process wait until one of its children has ended. You do not need to run these programs; predict their behavior from those rules.

(a) What does Program A print, in what order? Why does the parent print 7 rather than 12, even though the child added 5 first?

program-a.c
#include <stdio.h>                      // printf
#include <unistd.h>                     // fork
#include <sys/wait.h>                   // wait

int main(void) {                        // the program starts here, in one process
    int x = 10;                         // one variable, set before the fork
    pid_t pid = fork();                 // from here on, two processes run this code
    if (pid == 0) {                     // fork() returned 0: this copy is the child
        x = x + 5;                      // the child changes its x
        printf("child: x = %d\n", x);   // the child prints its x
        return 0;                       // the child ends here
    }                                   // end of the child's part
    wait(NULL);                         // the parent waits until its child has ended
    x = x - 3;                          // the parent changes its x
    printf("parent: x = %d\n", x);      // the parent prints its x
    return 0;                           // the parent ends here
}                                       // end of main

(b) For Program B: how many processes exist in total by the end (count the original), how many times is fork() called in total, and how many lines does it print? Explain how the count doubles.

program-b.c
#include <stdio.h>                      // printf
#include <unistd.h>                     // fork

int main(void) {                        // the program starts here, in one process
    for (int i = 0; i < 3; i++) {       // the loop body runs three times in the original program
        fork();                         // every process that reaches this line splits in two
    }                                   // end of the loop
    printf("hello\n");                  // every process that exists after the loop prints once
    return 0;                           // each process ends here
}                                       // end of main

(c) What does Program C print, and in what order? Is that order guaranteed every run? Describe the family: which process is the parent of which, and which one prints each letter.

program-c.c
#include <stdio.h>                      // printf
#include <unistd.h>                     // fork
#include <sys/wait.h>                   // wait

int main(void) {                        // the program starts here, in one process
    pid_t a = fork();                   // first fork
    if (a == 0) {                       // only the process for which this fork returned 0 enters here
        pid_t b = fork();               // second fork
        if (b == 0) {                   // only the process for which the second fork returned 0
            printf("C\n");              // prints one line
            return 0;                   // and ends
        }                               // end of the innermost part
        wait(NULL);                     // wait for the child made by the second fork
        printf("B\n");                  // prints one line
        return 0;                       // and ends
    }                                   // end of the middle part
    wait(NULL);                         // wait for the child made by the first fork
    printf("A\n");                      // prints one line
    return 0;                           // and ends
}                                       // end of main

(d) Suppose Program A's parent did not call wait(NULL) and instead kept computing for an hour, while the child ended within a millisecond. What state is the child in during that hour, what does the kernel still keep about it, and why does the kernel keep it?

Problem 7Amdahl's law

If a fraction f of a program's work can be spread perfectly over N cores and the rest (1 − f) must run on one core, the best possible speedup is: speedup = 1 / ((1 − f) + f / N). Efficiency = speedup / N.

(a) A program has f = 0.85. Fill in the speedup and efficiency (two decimal places for speedup, a percentage for efficiency). For the unlimited row, give the limit the speedup approaches and leave efficiency empty.

B2The starter program

Read it from top to bottom first; every line carries a comment. It runs four experiments, plus a fifth on request:

  1. Identity: three threads and three processes each print their process ID (pid), their parent's process ID (ppid) and their thread ID.
  2. Sharing: a thread and a process each add a marker to the same global list, and the main program then prints the list.
  3. CPU-bound work: the same calculation, split into 8 equal tasks, run by 1, 2, 4 and 8 threads and then by 1, 2, 4 and 8 processes. It prints each time and the speedup over one worker, then applies Amdahl's law.
  4. I/O-bound work: 8 tasks that only wait (a stand-in for waiting on a disk or network), run by 1 thread and by 8 threads.
  5. Thread count (--pause): keeps five threads alive and tells you how to count them with your operating system's own tools.
Why the program begins its real work under if __name__ == "__main__": — on Windows and macOS, Python starts each new process by running this file again from the top. The check keeps those new processes from launching the experiments all over again.
