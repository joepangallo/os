### 2. Replay order clamps a valid periodic-task workload — Partly fixed

The **exact earlier reproduction is fixed**: in `10.2/5`, set A period to **50**, then A needs to **30**. Values **[30, 50, 25, 50]** survive desktop → phone → desktop. The log records the period edit before the demand edit, instead of restoring in DOM order.

### 3. Asynchronous selector permits a synchronous programmed-I/O trace — Fixed

Executed `11.2/2`: **Asynchronous request** starts disabled with Programmed I/O selected. Interrupt-driven enables it. Selecting asynchronous and then returning to Programmed I/O changes the selected request to **Blocking request** and disables asynchronous again. The [new `syncCall()`](src/sections/11.2.js:298) synchronizes the selected mode before resetting the player. This resolves the previously selectable contradictory combination.

### 4. State probe cannot detect firmware configuration loss — Partly fixed

The specific firmware blind spot is fixed in **`--deep` mode**. Executed its actual edit function on `13.3/3`: it performed seven actions, selecting musl, BusyBox, squashfs and 16 MB, then toggling Networking, USB and Touch GUI. Its actual deep signature distinguishes Python 3 off from on through `aria-pressed` and text. Textarea values are now included in both modes. For this source-level signature check, JSDOM's missing rendered `innerText` was supplied from `textContent`; the pressed-state difference does not depend on that substitution.

Coverage remains partial. The [deep comparison](src/tools/state_probe.py:112) discards the phone signature when deciding whether state was lost; it compares only the final desktop state. Confirmed counterexample: `11.10/3`, Clear → first B cell, contains **B at 0.03 s** on desktop, **no writes** on phone, and B at 0.03 s again on return to desktop. Comparing desktop with itself therefore hides a real intermediate loss, even if that sequence is explicitly exercised.

The [deep action selection](src/tools/state_probe.py:35) also exercises only the first three eligible ordinary buttons and does not click SVG `[role=button]` elements. It misses new finding 2. Steps with no exercised controls still disappear without a separate unexercised-interaction inventory. Thus the reported 11 differences should not be described as all remaining state problems. Keep the broader deep mode, but add semantic phone assertions and explicit coverage reporting.

## New confirmed findings

### 1. Medium priority: compressing consecutive edits changes dependent state

**Reproduction / computation:** on `10.2/5`, set A period **50**, A needs **30**, A period **20**, A period **50**. Before relayout the sliders read **[20, 50, 25, 50]**: lowering the period correctly clamps demand to 20, and increasing the period does not raise it again. After phone reconstruction they read **[30, 50, 25, 50]**.

**Cause:** [recordAction](src/shell/shell.js:502) replaces the last edit whenever the next edit has the same control identity. It does not distinguish separate gestures, and even intermediate values within one drag can have lasting effects. The log becomes period 50 → demand 30 → period 50. It loses the period-20 callback that invokes [the demand clamp](src/sections/10.2.js:638).

**Recommendation:** preserve state-changing intermediate edits, or save the resulting task model atomically. Coalescing is safe only for controls whose discarded intermediate callbacks cannot affect other state. Add this decrease-then-increase sequence to the regression coverage.

### 2. Medium priority: SVG-button replay throws and aborts restoration

**Reproduction / computation:** on `12.9/4`, click **Dentry object** in the SVG diagram, then reconstruct for phone. The actual recorder logs `Dentry object#0`. Restoration reports **`TypeError: b.click is not a function`**, and selection returns to **VFS file object**.

**Cause:** [BTN_SEL](src/shell/shell.js:479) includes `[role=button]`, including the [SVG groups used by this lesson](src/sections/12.9.js:546). [Replay](src/shell/shell.js:522) assumes every matched element exposes the HTML `.click()` method. These SVG groups do not. The catch surrounds the entire replay and subsequent restoration, so the exception also prevents processing later actions and restoring tabs/player frames in that call.

**Recommendation:** support activation of SVG targets through their click event or a shared activation API. Isolate an individual failed action so it cannot prevent unrelated restoration. Include SVG interactions in the probe; ordinary `button` queries do not cover them.

### 3. Low priority: the 600-entry cap silently reverts later work, including Reset

**Reproduction / computation:** on `1.3/7`, click **Run to the end** 600 times, then **Reset**. This is a deliberately long-session boundary test; the run button remains enabled after completion. Before relayout, address 941 is **0002**. The log has 600 entries. Phone reconstruction replays the old runs and changes it to **0005**: Reset was dropped.

**Cause:** the [length guard](src/shell/shell.js:494) stops recording every subsequent event, rather than making a checkpoint or otherwise retaining current state. Even updating an existing final edit is blocked once the cap is reached, because the guard precedes edit compression. Reconstruction nevertheless continues to replay the stale prefix.

**Recommendation:** bound storage through explicit state checkpoints or safe compaction. Do not silently treat a stale prefix as the current state. The cap prevents unbounded entry growth, but it does not preserve correctness after the boundary.

### 4. Low priority: keyboard-flipped recap cards are lost on relayout

**Reproduction / computation:** render `10.3/8`, send Enter to its first recap card, and reconstruct for phone. The card's `aria-pressed` changes **false → true → false**. The action store remains empty after the keyboard activation. This test executes the actual key handler; native focus and visual animation were not tested.

**Cause:** the [shared flip-card keyboard handler](src/shell/shell.js:996) calls `flip()` directly. The [recorder listens only for click/input/change](src/shell/shell.js:644), and the snapshot contains no card states. Mouse activation is recorded; this equivalent keyboard activation is not. The same problem applies to other direct keyboard activation paths unless they independently save their state.

**Recommendation:** route keyboard and pointer activation through the same recorded action, or retain each card's state explicitly. Test both input methods through relayout.
